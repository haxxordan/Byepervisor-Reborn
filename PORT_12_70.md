# Firmware 12.70 port status

The 12.70 table in `include/offsets/12_70_candidate.h` is staged from the
unpublished EchoStretch ELF analyzed in
`/home/deep/src/ps5/testing/byepervisor-reborn-elf-analysis.md`. The table has
14 symbol and 21 gadget entries. Its order was checked against the 13.60
source table, and `PMAP_STORE`, `IDT_ARRAY`, and `COMMON_TSS` agree with public
kstuff-lite values after converting from the data base to the text base.
This is still a **candidate table**: most gadget bytes, the resume call site,
and the AP/HV offsets have not been independently verified on 12.70.

The regular `byepervisor_reborn.elf` exits early on 12.70, before modifying
kernel memory or installing a hook. The dedicated `preflight-1270.elf` is a
read-only diagnostic that has now passed on the launch-model console. Neither
ELF is a Linux loader.

## Confirmed on the launch-model 12.70 console

A bounded page-walk probe read `PMAP_STORE` successfully and derived a direct
map base of `0xffff825900000000`. The kernel text range contained eight sampled
2 MiB spans: six 2 MiB PDE leaves and two 4 KiB-table PDEs. That confirms the
upstream page loop's unconditional `find_pte()` descent would treat mapped
kernel text as a page table on this console. Commit `e65f5fa` makes the common
walker reject 1 GiB and 2 MiB leaves, skips `find_pte()` for large text PDEs,
and fixes the physical-address mask to bits 12–51. The corrected HV payload
has not been run on 12.70.

The original write wrapper ignored `kernel_copyin` errors, so the captured
panic log cannot prove which bad write succeeded. The old Discord ELF remains
unsafe to rerun.

The 12.70 preflight then completed with `PREF1270,1,end,ok`:

- `PMAP_STORE` yielded PML4 `0xffff8259195b4000`, CR3 `0x195b4000`, and
  direct-map base `0xffff825900000000`. Candidate `DMPML4I=260` and
  `DMPDPI=356` reconstruct that same base.
- The carrier VA `0xffff82593ffff000` resolves through a present 2 MiB PDE
  leaf (`0x000000003fe001e3`). Its PML4 entry has NX set before the loader's
  page-table changes. The corrected walk must stop at that PDE.
- The candidate cave's oracle, state, and scratch qwords were all zero. The
  existing `#DB` gate is present, selector `0x20`, interrupt-gate type `0xe`,
  and its handler falls inside the kernel image. Core 0 TSS RSP0 is canonical;
  IST6 is zero before any hook is installed.

These observations support the candidate **data** offsets and page layout.
They do not validate the resume call instruction, ROP gadgets, or AP-time HV
globals. The shared `kread`/`kwrite` wrappers now return SDK copy errors to
callers; single-value reads initialize their output to zero on failure. More
error handling is still needed around the full hook path.

## Read-only preflight

Build from this directory with the configured PS5 payload SDK:

```sh
make preflight-1270.elf
```

The preflight checks firmware and SDK kernel bases, reads the pmap fields,
compares candidate direct-map globals with the pmap-derived base, walks the
`0x3ffff000` physical carrier mapping without modifying it, and reads three
data-cave qwords plus the existing `#DB` gate and core-0 TSS fields. It reports
lines beginning `PREF1270,1,` and shows a short completion or stop
notification. It does not read execute-only kernel text, install a hook,
request rest mode, or write target page tables. Invalid kernel reads can still
panic a console, so it is a bounded diagnostic rather than a zero-risk test.

## Remaining gates before a full 12.70 attempt

1. Independently validate the candidate resume call site and reachable gadget
   instructions against 12.70 executable bytes. Their presence in an ELF table
   is not proof that they have the expected effects on this console.
2. Determine whether the 12.70 AP window has usable hypervisor heap/`pcpus`
   globals. The 11.60 port reports those globals were zero during its AP
   window and used guarded runtime VMCB discovery instead. Its fixed physical
   heap range must not be copied to 12.70 without measurement.
3. Review the hook's error handling and stage markers before any exception or
   rest-mode run. The existing GPU DMA route to executable kernel bytes
   rewrites GPU page-table entries and needs firmware-specific GPU offsets;
   it is not a read-only substitute for this gate on 12.70. The one decrypted
   PUP kernel block saved so far does not expose a recognizable kernel header.

## Intended post-resume milestone

The full payload changes the kernel text page permissions before rest mode,
then uses the resume/AP path to defeat the remaining HV protection. On a
successful return, `main.c` reads and notifies the first eight bytes of kernel
`.text`. A stable post-resume state should then allow a separate full kernel
dump and patching. The eight-byte notification alone demonstrates a readable
sample, not that a full dump has been completed or that Linux boots. Linux
loader and kernel support remain separate work.
