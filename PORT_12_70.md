# Firmware 12.70 port status

The repository currently runs only its 13.00, 13.20, and 13.60 offset tables. The 12.70 offsets below are **partial research values**, not a working exploit. `kdlsym.c` does not include `12_70_partial.h`; on 12.70 the payload now reports unsupported firmware and exits before any kernel writes or hook setup. Nothing in this checkout has been run on the console.

## Located values

The local PS5 payload SDK maps the 12.70 kernel text base `0xD50000` below the data base. EchoStretch's kstuff-lite 12.70 table gives the following values relative to the data base. Adding `0xD50000` converts them to this repository's text-relative format:

| Byepervisor entry | kstuff-lite data-relative | text-relative for this repo |
| --- | ---: | ---: |
| `KERNEL_SYM_PMAP_STORE` | `0x2E1CFB8` | `0x3B6CFB8` |
| `KERNEL_SYM_IDT_ARRAY` | `0x2E88300` | `0x3BD8300` |
| `KERNEL_SYM_COMMON_TSS` | `0x2E8AFE0` | `0x3BDAFE0` |
| `KERNEL_GADGET_IRETQ` | `-0xA9CB53` | `0x2B34AD` |

The same conversion exactly reproduces this repository's 13.00 values for all four entries, using kstuff-lite's 13.00 table and the SDK's 13.00 text/data gap of `0xCB0000`. This checks the coordinate system; it does not validate the 12.70 instruction bytes on this console.

## Still needed

- The `hv_mp_startup` call site, its original AP init vector, and a suitable executable data cave for the 12.70 kernel.
- The remaining ROP gadgets, especially the resume-context tail, stack pivot, debug-register write, and memory-store gadgets. Copying 13.xx gadget addresses into 12.70 would be unsafe.
- Confirmation that the two hypervisor data offsets used by `break_hv_payload` remain valid on 12.70. Their equality across the three 13.xx tables is only a clue.
- A review of the resume hook's instruction assumptions and gadget side effects against a decrypted 12.70 kernel image.

`KERNEL_SYM_DMPML4I` and `KERNEL_SYM_DMPDPI` are used by `kdldmap()`; `KERNEL_SYM_PML4PML4I` is used only by the currently unused `pmap_kextract()`. The kstuff-lite implementation derives the direct-map base from `kernel_pmap_store + 0x20` and `+0x28`, which may remove the need to locate those globals after we validate it for this port. `SYS_GETUID` is used only by the optional `KHOOK_TEST` path; `PRINTF` and `ACPI_SLEEP_MACHDEP_HOOK` appear unused here.

The most direct next input is a decrypted 12.70 kernel from the staged PUP workflow in `/home/deep/src/ps5/testing/pup-1270`. That would let us locate and disassemble the missing resume targets and gadgets offline before considering any hook or rest-mode test.

## Safety changes in this checkout

- Unsupported firmware now returns immediately after notifying the user. Upstream printed an error but continued into kernel operations with zero offsets.
- The post-resume demonstration write of `0x41414141` into kernel text was removed. That write was unnecessary for reading the first bytes of text and would corrupt a live instruction stream.
